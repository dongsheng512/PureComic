# 漫画阅读器功能排期

| 字段 | 内容 |
|------|------|
| **产品** | PureComic |
| **日期** | 2026-08-13 |
| **人力** | 1 人（主路径） |
| **平台** | 先 macOS arm64；Win/Linux 随桌面壳一起带，不单独立项 |
| **原则** | 本地书库管「有哪些本」；阅读器管「当前这一本」；增强管「这一本怎么处理」 |
| **修订** | 2026-08-13：纳入书库页（L0–L2），云同步仍不做 |

一句话目标：**书架上找到书 → 打开就能读 → 原图先出、增强页替换 → 读到哪可优先增强。导出 CBZ 仍是主交付。**

---

## 总览

| 阶段 | 名称 | 周期 | 可否独立上线 | 用户能做什么 |
|------|------|------|----------------|--------------|
| **R0** | 跟读任务 | 第 1 周 | 内部可用 | 打开正在跑 / 已跑完的 job，翻页；增强完的页换图 |
| **R1** | 独立阅读 | 第 2–3 周 | 阅读可交付 | 不建任务也能打开 Folder/ZIP/CBZ；单页阅读器成型 |
| **L0** | 最近书架 | 第 3 周（与 R1 重叠） | **第一版可交付** | 默认落地为书库页：最近打开 + 任务/导出，封面进阅读 |
| **R2** | 边读边增强 | 第 4–6 周 | 阅读器成立 | 阅读中开增强；当前页 ±3 优先；原图/增强无缝替换 |
| **R3** | 阅读体验 | 第 7–8 周 | 体验打磨 | RTL、适应宽/高、本地进度、双页（可选） |
| **L1** | 本地书库 | 第 8–10 周 | **书库成立** | 添加根目录、扫描 CBZ/文件夹、封面墙、搜索、继续阅读 |
| **L2** | 书库状态 | 第 10–11 周 | 和增强打通 | 卡片显示未增强/增强中/已增强；从书库开增强或打开导出 |
| **X** | 明确不做 | — | — | 云进度、在线源、标签体系、实时滤镜、注释层 |

缓冲：每阶段末留 **0.5 周**。阅读器到 R2 约 **6 周**；带完整本地书库约 **11–12 周**。若要 4 周先发：**R0 + R1 + L0**（有书架，无文件夹扫描、无插队增强）。

依赖：增强主路径（建任务、取消、导出、引擎切换）保持可发布。阅读器 **不阻塞** 现有增强 GA。

---

## 产品边界（全程有效）

**做**

- 一本源或一个 job 的全屏/大窗阅读
- 页状态：原图 / 增强中 / 已增强 / 失败
- 已增强页用工作目录或导出结果换图
- R2 起：阅读位置驱动优先队列
- **本地书库页**（默认首页）：封面、进度、增强状态；用户指定根目录扫描
- 从书库进入阅读 / 开始增强 / 打开导出

**不做（X）**

- 账号、多设备同步、在线图床
- 在线源 / 插件源（Tachiyomi 路线）
- 复杂标签、系列树、评分社区
- 滚动实时超分（Magpie 路线）
- 全盘自动扫描（必须用户点选根目录）
- PDF / 7z 阅读（跟增强格式列车走）
- 翻译、OCR、批注

**技术硬约束**

- 图走自定义协议或 `convertFileSrc`，**禁止** PNG Base64 data URL（现预览不可复用为阅读）
- 同时只占一把 `GpuLock`；阅读中途预览/第二本增强要排队并有文案
- 页序与 `validate_source` / `page_names` 一致
- 禁止覆盖源文件
- 书库是本地索引（app data 里一份 `library.json`），**不**把漫画文件拷进书库
- 封面缩略图单独缓存，不走阅读器用的全幅图

## R0 · 跟读任务（第 1 周）

验证「页做完就能换图」，不改调度。

### 交付

| 项 | 说明 |
|----|------|
| API | `get_job_pages(jobId)`：index、name、status、可展示的 in/out 路径 |
| 协议 | `comic-page://` 或 asset 转换，只读 job 工作目录 |
| UI | 任务队列「阅读」；单页大图 + 上一页/下一页 + 页码 |
| 替换 | 听 `job://progress`，当前页 `Done` 则切到 `out_path` |
| 角标 | 原图 / 已增强 / 失败 |

### 不做

独立打开未建任务的文件；插队增强；双页；条漫连续滚。

### 验收

- 跑一本 ≥20 页 CBZ，解压完成后可打开阅读器，先显示 `in/`
- 增强过程中翻页不卡死主界面；已完成页刷新后为增强图
- 切走阅读器再回来，页码仍在（会话内即可）
- 任务失败页仍能看原图
- 连续翻 50 页，WebView 内存不明显泄漏（只留当前 ±1 页）

### 主要改动面

`scheduler` / `lib.rs` 新命令；`api.ts` + 类型；`App.tsx` 阅读表面（可先全屏层，不必新窗口）。

## R1 · 独立阅读（第 2–3 周）

第一版对外可用的阅读器。

### 第 2 周 · 按页读源

| 项 | 说明 |
|----|------|
| API | `open_reader(source)` → 校验 + `pageCount` + `pageNames` |
| 抽页 | 复用 `extract_page_to_png`，缓存到 `work/reader/<hash>/` |
| 预取 | 后台抽当前页的下一页；离开后删临时 PNG（可保留最近 N 页） |
| 入口 | 书库卡片、增强页选源后「阅读」、任务队列「阅读」 |
| 窗口 | 阅读模式拉高窗口或独立窗（建议 ≥900 高）；设置区可收起 |

格式：**Folder / ZIP / CBZ**。CBR / EPUB / MOBI 能抽就开，失败给现有中文错误，不单独立项。

### 第 3 周 · 阅读壳

| 项 | 说明 |
|----|------|
| 操作 | 方向键 / 点击左右缘 / 空格翻页；`Esc` 回首页 |
| 显示 | 适应宽度（默认）、适应窗口；浅/深底跟主题 |
| 页码 | 输入跳转；进度 `12 / 180` |
| 空态 | 无图、损坏页、加密 zip 的明确提示 |
| i18n | zh-CN / en |

### 验收

- 不创建 enhance job 即可读完一本 CBZ
- 页序与增强预览、校验结果一致
- 关阅读器后临时缓存有上限（例如 ≤30 页或 ≤500 MB）
- 增强 Tab / 预览 Tab / 医生 Tab 行为不变

### 里程碑 **Reader-1**

可对外说：PureComic 能当本地 CBZ 阅读器打开刚要增强的书。落地页见同期 **L0**。

## R2 · 边读边增强（第 4–6 周）

阅读器真正区别于普通看图软件的阶段。

### 第 4 周 · 会话模型

| 项 | 说明 |
|----|------|
| 会话 | `ReaderSession`：source、jobId?、pageIndex、方向、缩放 |
| 开增强 | 阅读器内「开始增强」：沿用当前引擎/预设，创建或 resume **同一源** 的 job |
| 绑定 | 一源一 job；阅读器挂到该 job，页表与 R0 相同 |
| UI | 顶栏：进度、ETA、取消；页角标四态 |

解压未完成时：当前页按需抽原图，不阻塞翻页。

### 第 5 周 · 优先窗口（核心）

目录整本批处理无法「先做第 40 页」，本周改调度。

**推荐策略（实现简单、够用）：**

1. 阅读模式下默认仍目录批处理（吞吐）。
2. 用户停在页 `N` 超过约 400ms，且 `N` 尚未 Done：
   - 取消当前 batch（已有 `CancellationToken`）；
   - 把 `N … N+2`（可配）插到待处理队列头；
   - 再对剩余 Pending 开下一次目录批处理。
3. 仍只持一把 `GpuLock`。已写入 `out/` 的页不重做。

备选（更晚）：纯逐页 + 优先级堆。吞吐差，只当目录取消抖动太大时再换。

### 第 6 周 · 替换与稳定

| 项 | 说明 |
|----|------|
| 热替换 | 当前页 Done 后无闪白切到增强图（可淡入） |
| 对比 | 长按或按键看原图（复用 before，不走预览 data URL） |
| 打包 | 增强全部完成后仍自动导出；阅读继续读 `out/` 或导出 CBZ |
| 冲突 | 阅读中禁止再开第二本 GPU 任务；队列里其他 job 等待 |
| 文案 | 「阅读优先：先处理第 N 页」 |

### 验收

- 从第 1 页读，前几页在目录批处理自然完成后替换（取消次数少）
- 跳到第 40 页：约 1 个 GPU 空档后开始出第 40–42 页，不必等 1–39 全部完成
- 取消 / 失败不影响已读原图
- 整本完成后导出路径与现在一致；resume 后再打开阅读器页状态正确
- fixture 级吞吐：阅读闲置（不跳页）时不低于现目录批处理的约 85%

### 里程碑 **Reader-2**

可对外说：边读边增强，读到的页优先出图。

## R3 · 阅读体验（第 7–8 周）

不改管线，只补阅读习惯。可与 R2 收尾重叠。

| 优先级 | 功能 | 说明 |
|--------|------|------|
| P0 | 从右往左 | 日漫默认可开；记住每本（本地 `localStorage` 或小 json） |
| P0 | 阅读进度 | 写入书库条目（源路径哈希 → 页码）；书库「继续阅读」与阅读器共用 |
| P0 | 适应宽 / 高 / 原尺寸 | 滚轮或 `+/-` 缩放当前页 |
| P1 | 双页 | 宽窗下左对右或右对左；条漫自动关 |
| P1 | 条漫 | 长图连续竖滚；与单页模式互斥 |
| P2 | 独立阅读窗 | 主窗继续排队，阅读窗只翻页 |
| P2 | 缩略图条 | 底部条，已增强页可点标记 |

### 验收

- RTL 翻页方向与页序正确
- 重启应用后同一本回到上次页
- 双页/条漫不破坏 R2 页状态与优先窗口（优先仍按逻辑页号）

### 里程碑 **Reader-3**

日常能用来「看完一本」，而不只是检查增强效果。

## L0 · 最近书架（第 3 周，与 R1 重叠）

书库页先上，数据先用「做过的事」，不扫盘。

### 信息架构

现有 Tab：`增强 | 预览 | 医生`。改为默认落地 **书库**：

`书库 | 增强 | 预览 | 医生`

- **书库**：找书、继续读、看增强状态
- **增强**：拖入新书、调引擎/预设、建任务（现首页设置卡）
- 阅读器是全屏层或独立窗，不是第四个常驻 Tab

### 交付

| 项 | 说明 |
|----|------|
| 索引 | 打开过的源、创建过的 job、已导出路径，写入 `library.json` |
| 卡片 | 封面（第 1 页缩略图）、文件名、页数、上次打开时间 |
| 操作 | 单击阅读；菜单：去增强、打开所在文件夹、从书架移除（不删文件） |
| 空态 | 尚无书 → 引导「添加文件」或切到增强页拖入 |
| 封面 | `extract` 第 0 页 → 最长边约 360px JPEG，缓存 `work/library/covers/` |

### 验收

- 增强过或阅读过的书出现在书库，重启还在
- 源文件被移走：卡片标「文件缺失」，可移除，不崩
- 同一路径不重复占两张卡（job 挂到已有条目上）
- 封面生成失败仍显示占位，不影响列表

### 里程碑 **Library-0**

可对外说：打开应用先看到书架，点进去就能读。

## L1 · 本地书库（第 8–10 周）

用户指定根目录，才算真正的书库。放在 R3 之后，复用阅读进度与抽页。

### 第 8 周 · 根目录与扫描

| 项 | 说明 |
|----|------|
| 添加根 | 选文件夹；可多个；只扫这一层或一层子目录（默认一层，避免整盘） |
| 识别 | Folder（内含图）、`.cbz` / `.zip`；CBR 有 unrar 则收录 |
| 刷新 | 手动「扫描」；不做开机全盘监听（FSEvents 列为 L2 后可选） |
| 忽略 | 隐藏文件、`_x2` 导出若与源同目录可标成「增强结果」而不是第二本 |

### 第 9 周 · 封面墙

| 项 | 说明 |
|----|------|
| 布局 | 网格（默认）/ 列表；浅色深色跟主题 |
| 搜索 | 按文件名、父文件夹名过滤 |
| 排序 | 最近阅读、最近添加、文件名 |
| 封面队列 | 后台低优先级抽第 1 页，不抢 `GpuLock`（只解码，不增强） |

### 第 10 周 · 继续阅读

| 项 | 说明 |
|----|------|
| 进度条 | 卡片底部 `12 / 180`（R3 已写入的进度） |
| 继续 | 点封面从上次页打开；菜单「从头阅读」 |
| 缺失 | 根目录里文件消失 → 扫描后标缺失，不自动删索引（用户确认再清） |

### 验收

- 添加含 50 本 CBZ 的目录，扫描 < 数秒出列表，封面随后填上
- 不把导出的 `*_x2.cbz` 和源当成两本无关的书（能关联则叠在一张卡的「已增强」上）
- 搜索、排序不卡；移除根目录不删用户漫画文件
- 书库打开阅读、增强页拖入新建，两边索引一致

### 里程碑 **Library-1**

可对外说：指定漫画文件夹，封面墙浏览、接着上次读。

---

## L2 · 书库状态（第 10–11 周）

把增强队列画到卡片上。依赖 R2 的 job 绑定。

| 项 | 说明 |
|----|------|
| 角标 | 未增强 / 增强中（页进度）/ 已增强 / 失败 |
| 快捷 | 卡片「增强」：用当前默认引擎建 job，可停在书库看进度 |
| 打开导出 | 已增强 → 读增强结果（优先 `outputPath`）或读源 |
| 过滤 | 全部 / 未增强 / 增强中 / 已增强 |
| 冲突 | 已有一本在增强：其他卡片点增强进入队列等待，文案与 R2 一致 |

### 验收

- 书库里点增强，队列与增强页看到同一 job
- 增强中卡片进度与 `job://progress` 同步
- 完成后角标变为已增强，点阅读默认进增强版，可改回源

### 里程碑 **Library-2**

可对外说：书架上看哪些增强完了，直接读增强版。

## 书库数据（L0 起）

存在 app data，例如 `{app_data}/library.json`。漫画本体仍在用户原路径。

```
LibraryEntry
  id            规范化绝对路径的稳定哈希
  path          源路径
  kind          folder | cbz | zip | cbr | …
  title         先用文件名 / 文件夹名（ComicInfo 解析不进本排期）
  pageCount
  coverRel      缩略图相对 work 路径
  lastReadPage
  lastOpenedAt
  addedAt
  jobId?        最近一次 enhance job
  enhanceState  none | running | done | failed
  outputPath?   导出 CBZ / 文件夹
  missing       源不在了
```

扫描与封面 **不** 占用 GPU 锁。一源一条；job、导出都挂这条上。

## 风险与缓冲

| 风险 | 影响 | 对策 |
|------|------|------|
| 大图解码撑爆 WebView | R1 翻页卡死 | 协议直出 JPEG；只挂载当前 ±1；2× 页限制最大显示边 |
| 取消 batch 太勤 | R2 吞吐崩 | 防抖 400ms；仅当目标页未 Done 才取消；阅读闲置恢复整本 batch |
| ZIP 解压与按页抽取抢文件 | 偶发读失败 | 抽取走只读打开；解压中阅读只用按需抽页 |
| `out/` 打包后被清 | 读到空白 | 完成后改读导出 CBZ 或保留 `out/` 到用户关阅读器 |
| 阅读器拖垮增强主路径 | 发布风险 | R0–R1 / L0 纯增量；R2 调度改动用 feature flag `readerPriority` |
| 扫描扫进整盘或导出副本 | 书库重复、极慢 | 只扫用户添加的根；默认一层子目录；`_x2` 与源合并 |
| 封面后台打满磁盘 | work 膨胀 | 缩略图限最长边 360、JPEG；缓存上限（如 500MB）LRU |

---

## 决策已冻结（排期按此执行）

1. 第一期对外是 **R1 + L0**（能读 + 最近书架），不是等 R2 / L1。
2. 「边增强」默认是 **原图先读，好了再换**；不是「必须等增强图才能翻页」。
3. 同时只增强一本；阅读优先通过 **取消并重排目录批处理** 实现。
4. 书库只做 **本地索引 + 用户指定根目录**；不做云同步、在线源、全盘扫描。
5. 应用默认打开 **书库页**，增强页保留给拖入和调参。

若要压缩到 4 周发一版：只做 **R0 + R1 + L0**。文件夹扫描（L1）和跳页优先（R2）放到下一轮。
